EXAMPLE SCENARIO · NOT A CASE STUDY

Self-service fronts,
before a kiosk is specified.

Ticketing, visitor check-in and information kiosks raise the same early questions: public use, cover durability, brightness and how the touch panel meets the host. This page is a framework for that conversation. It is not a deployed kiosk and it is not a payment or security approval.

Bring the enclosure and the task list. Finished drawings can wait.

EXAMPLE SCENARIOS

What the brief would need to settle.

EXAMPLE 01

A public information or wayfinding front

Viewing height, outdoor or indoor light, and whether the cover has to survive frequent cleaning.

EXAMPLE 02

A check-in or ticketing panel

Outline, cable exit and the host interface. Duty cycle belongs in the brief, not in a generic claim.

EXAMPLE 03

A fixed-key control beside a screen

Some kiosks need a keypad and a display. Those are compared as routes, then confirmed for the unit.

No customer logo, site name or measured field result is attached to these examples. If a program later becomes a case study, it needs the customer’s confirmation first.

PRODUCT ROUTES TO COMPARE

The front is still a configuration.

On-screen menus

Custom PCAP touch panels

Sensor, cover and controller for the opening in the kiosk.

The public surface

Cover lenses and panels

Glass, PC or PMMA, print and mounting, reviewed with the touch layer.

Fixed controls

Capacitive touch keypads

When the actions are a known set of keys rather than a free screen.

Display plus touch

Touch display assemblies

Display module, touch and matched boards or cables, scoped per host.

Touch, display and optical bonding stay separate routes. A kiosk brief names which of them is in scope; delivery is set in the project review.
